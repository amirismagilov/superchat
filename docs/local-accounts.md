# Локальная проверка настоящих аккаунтов на macOS и Linux

Распакуйте проект на своём компьютере. `Start.command` поднимает отдельный локальный набор контейнеров и открывает [http://127.0.0.1:8080](http://127.0.0.1:8080). После входа можно подключить свои Telegram, WhatsApp и MAX и обмениваться реальными сообщениями. Аккаунты автоматически не подключаются, сообщения автоматически не отправляются. SMS требует отдельного Android-шлюза.

Среда, в которой подготовлен проект, — облачный Linux. Она не предоставляет доступа к вашему Mac, браузеру, телефону или установленному Docker. Проверка конфигурации/контейнеров в облаке не означает, что установка уже выполнена на вашем компьютере. Реальные messenger login/send/receive и работа именно на macOS требуют вашей локальной проверки.

`scripts/install_mac_local.sh <полный-SHA>` скачивает зафиксированную версию из
GitHub в `~/Projects/omnicrm-local`, запускает установленный Docker Desktop и
открывает локальную CRM на порту `18581`. Python и Git на Mac не требуются.
Повторный запуск использует существующую папку и её ключи; это не автоматическое
обновление исходников. Для запуска уже установленной копии используйте
`bash "$HOME/Projects/omnicrm-local/Start.command"`, для остановки — такой же путь
к `Stop.command`. Остановка сохраняет аккаунты и историю.

Это отдельная локальная база. Настройки Telegram API ID/hash нужно указать в ней
один раз, WhatsApp — связать по QR. Установщик не обращается к VDS и не переносит
его учётные данные. Если в Docker уже найдены данные проекта `omnicrm-local`,
а исходного `.env.local-docker` в выбранной папке нет, запуск остановится: нужно
использовать прежнюю папку, чтобы сохранить ключи шифрования и доступ к базе.

## Первый запуск

1. Установите [Docker Desktop](https://docs.docker.com/get-started/get-docker/) для своего Mac — Apple Silicon или Intel. На Linux нужны Docker Engine и плагин Docker Compose v2. Запустите Docker и дождитесь состояния «running». Launcher не устанавливает системные пакеты и не вызывает `sudo`.
2. Распакуйте весь архив в обычную папку, например `~/Projects/omnicrm`. Не запускайте файлы прямо из просмотрщика архива. Для пилота с несколькими аккаунтами можно начать с 4 ГБ памяти Docker и 10 ГБ свободного места; это ориентир для настройки, а не измеренная ёмкость.
3. На Mac откройте `Start.command` двойным щелчком. Если Finder не запускает `.command`, выполните из Terminal:

   ```bash
   cd ~/Projects/omnicrm
   bash scripts/local_start.sh
   ```

   На Linux используется та же команда. Отдельная установка Python, Node.js, PostgreSQL или WAHA на компьютер не нужна: инициализатор тоже работает в контейнере.
4. Дождитесь сборки и скачивания образов. При первом запуске это может занять несколько минут. После готовности API, worker, PostgreSQL и WAHA откроется браузер. Если автоматическое открытие недоступно, откройте адрес, напечатанный как `Ready`.
5. Нажмите кнопку локального входа. Она создаёт локальную административную сессию для тестирования. Затем добавьте нужный канал и свои реквизиты входа.

Этот запуск использует `LOCAL_TEST_MODE=true`, `DEMO_MODE=false`, `ENABLE_EXPERIMENTAL=true`. Доступ к UI/API опубликован **только на `127.0.0.1`**. Пароля перед локальным входом нет: любой пользователь вашего компьютера с доступом к этому порту может получить локальную административную сессию. Не публикуйте этот порт в локальную сеть/Интернет, не подключайте tunnel/reverse proxy и не используйте такую конфигурацию для команды. Для сервера предусмотрен отдельный [production-процесс](operations.md) с CRM JWT.

## Подключение каналов

| Канал | Что подготовить | Как проверить |
|---|---|---|
| Telegram — аккаунт менеджера | Собственный аккаунт, рабочий номер; администратор один раз задаёт `api_id` и `api_hash` приложения компании из [my.telegram.org → API development tools](https://my.telegram.org/apps); пароль 2FA, если включён | «Добавить канал» → Telegram → номер → код → пароль при запросе. Альтернатива — QR через Telegram → «Настройки» → «Устройства». Дождаться автоматического подтверждения, затем синхронизировать историю и проверить переписку с другим аккаунтом |
| WhatsApp — подключённое устройство | Рабочий WhatsApp на телефоне | «Добавить канал» → WhatsApp → отсканировать QR через «Связанные устройства» на телефоне. Подключение подтвердится автоматически. Открыть диалог или указать номер с `+`, проверить сообщения в обе стороны |
| MAX — аккаунт менеджера | Уже зарегистрированный аккаунт в штатном приложении MAX | «Подключить канал» → MAX → QR → подтвердить вход на телефоне → «Перейти в чаты». Альтернатива — «Войти по номеру телефона», код и пароль MAX при запросе. Проверить переписку с другим аккаунтом; если новый номер недоступен для поиска, выбрать существующий диалог или известный User ID |
| SMS — рабочая SIM | Android-устройство с SIM и собственный [SMS Gateway](https://docs.sms-gate.app/), доступный из Docker | В `.env.local-docker` задать `SMS_GATEWAY_URL`, снова запустить launcher, затем указать учётные данные шлюза, Device ID и webhook signing key. Отправка работает через этот шлюз; входящие требуют отдельно доступного callback |

WhatsApp linked-device и MAX personal — экспериментальные адаптеры. Их включение здесь позволяет провести пилот, но не гарантирует отсутствие ограничений/отзыва сессии со стороны мессенджера. QR, код входа и пароль вводите только в локальную форму; не присылайте их в чат поддержки. Библиотека MAX уже включена в Docker-сборку.

Telegram читает доступную облачную историю личных диалогов; Secret Chats не поддерживаются. WhatsApp/MAX импортируют историю, которую отдаёт связанное устройство/SDK, по умолчанию за 30 дней. Первоначальный импорт может занимать время. Поддержана отправка текста; вложения пока отображаются отметкой без скачивания/отправки файлов. Подробности: [Telegram](telegram-adapter.md), [WhatsApp и MAX personal](personal-adapters.md).

Для Telegram, WhatsApp linked-device и MAX personal входящие получаются через исходящее соединение/polling, поэтому публичный callback не нужен. Официальные WhatsApp Cloud API и MAX Bot, а также входящие SMS требуют маршрута webhook к серверу. Провайдер в Интернете не может вызвать `127.0.0.1` вашего компьютера. Полную webhook-проверку выполняйте на отдельном HTTPS-развёртывании с отключённым `LOCAL_TEST_MODE`; не открывайте локальный административный режим через tunnel. Для шлюза на самом Mac адрес `localhost` внутри контейнера означает контейнер: используйте доступный адрес шлюза, например `host.docker.internal` на Docker Desktop, и проверяйте его правила доступа.

## Остановка, повторный запуск и данные

Для остановки откройте `Stop.command` либо выполните:

```bash
bash scripts/local_stop.sh
```

Скрипт останавливает контейнеры, сохраняет БД, сессии и ключи. Для повторного запуска снова откройте `Start.command`. Если код не менялся и образ уже собран:

```bash
bash scripts/local_start.sh --no-build
```

Состояние:

```bash
bash scripts/local_status.sh
```

Docker project называется `omnicrm-local`. Он использует свои named volumes: `omnicrm-local_postgres-data`, `omnicrm-local_waha-sessions`, `omnicrm-local_waha-media`. Это отдельные данные от production `compose.yaml` и SQLite-демо. Файл `.env.local-docker` создаётся однажды с правами `0600`; повторный запуск сохраняет его значения. Он исключён из git и Docker build context. Launcher также исключает случайную подстановку унаследованных `DATABASE_URL`, encryption/JWT/WAHA ключей из окружения другой разработки.

**Сохраните `.env.local-docker` вместе с доступом к резервным копиям.** Потеря encryption key лишит доступа к зашифрованным сессиям, а смена DB password без согласованного изменения PostgreSQL сломает вход в БД. Простое повторное создание файла не восстанавливает старые ключи. Не удаляйте volumes и не запускайте `down -v` для устранения ошибки старта. Закрытие браузера не останавливает worker; `Stop.command` останавливает его. Чтобы отозвать авторизацию у провайдера, используйте «Отключить» в UI либо управление связанными устройствами в самом мессенджере.

WAHA хранит WhatsApp-сессии отдельно от основной БД. Шифрование Fernet на эти Docker volumes не распространяется; защитите свой пользовательский аккаунт, диск и резервные копии компьютера.

## Порт и диагностика

Если `8080` занят, при запуске из Terminal задайте свободный порт:

```bash
LOCAL_PORT=18080 bash scripts/local_start.sh
```

Для постоянного изменения, в том числе для двойного щелчка, отредактируйте только `LOCAL_PORT` в `.env.local-docker`. Не публикуйте содержимое этого файла. Launcher не открывает браузер, если health checks не пройдены. Проверка `/api/runtime` должна вернуть `local_test: true` и `demo: false`; статус health подтверждает процесс и БД, а не вход в каждый мессенджер.

| Симптом | Действие |
|---|---|
| Docker не найден или daemon недоступен | Установить/запустить Docker Desktop; на Linux проверить собственный доступ к Docker socket. Launcher ничего не меняет в системных правах |
| Compose не знает `--wait-timeout` | Обновить Docker Desktop или Compose v2 plugin |
| Ошибка скачивания/сборки | Проверить доступ Docker к Docker Hub и Python package registry, свободное место и настройки корпоративного proxy. После исправления повторить запуск; ключи сохранятся |
| `port is already allocated` | Использовать другой `LOCAL_PORT` |
| WAHA/API остаётся unhealthy | Выполнить `local_status.sh`; изучить журналы нужного контейнера в Docker Desktop. Не публиковать дамп переменных среды, QR или содержимое сообщений |
| Канал долго в connecting / не приходит код | Проверить исходящую сеть компьютера, состояние штатного приложения и ограничения аккаунта. Сетевой запрет облачной среды разработки не является проверкой вашей домашней/рабочей сети |
| WhatsApp отправляет, но входящих нет | Запустить `scripts/diagnose_whatsapp_incoming.py` внутри worker (пример ниже). Отчёт сравнивает последние сообщения шлюза с БД по ID, не выводя текст, номера и ключи |
| После обновления отказал `migrate` | Сохранить данные и проверить сообщение ошибки. Поддерживаются известные версии `0001_initial`, `0002_telegram_integration` и добавление таблиц `0003_inbox`; неизвестная или изменённая схема требует отдельного разбора. Для Selectel использовать [инструкцию обновления и отката](server-update.md) |

Для корпоративного/managed build с доверенным CA можно задать `LOCAL_BUILD_CA_FILE=/полный/путь/ca.pem`; launcher передаст его как BuildKit secret, не сохраняя в образе. Также распознаётся `CODEX_PROXY_CERT`. Это только доверие на этапе установки Python-зависимостей: runtime proxy/CA настраиваются отдельно. Не отключайте TLS verification. Опция `--no-open` полезна для headless проверки.

Если диагностический скрипт есть в вашей копии исходников:

```bash
docker compose -p omnicrm-local --env-file .env.local-docker -f compose.local.yaml \
  exec -T worker python - < scripts/diagnose_whatsapp_incoming.py
```

`gateway_history.samples[].already_in_account_db=false` для свежего входящего означает, что сообщение уже доступно в WAHA, но ещё отсутствует в базе этого аккаунта. Если оно есть в БД, а в выбранном диалоге не видно, нужно проверить идентификаторы диалогов и PN/LID. Пустой ответ WAHA сам по себе не устанавливает причину: отчёт делает ограниченную выборку, не меняя подключение.

Для исходной локальной установки `f4f533a` предусмотрен отдельный patch launcher `scripts/update_mac_whatsapp_incoming.sh FULL_COMMIT_SHA [LOCAL_DIRECTORY]`. Он извлекает только адаптер из зафиксированного GitHub commit, проверяет исходную версию файла, сохраняет резервную копию и прежний образ, собирает новый и обновляет только API/worker. Файл ключей, БД, сессия WAHA и маркер основной версии остаются на месте; при ошибке сборки или проверки приложения выполняется откат. Уже изменённый вручную адаптер не перезаписывается. Это целевое исправление получения сообщений, а не полное обновление проекта. Повторный `install_mac_local.sh` существующие исходники не обновляет.

Обновление MAX ставится отдельным `scripts/update_mac_max.sh FULL_COMMIT_SHA [LOCAL_DIRECTORY]` для той же исходной установки, в том числе после WhatsApp patch. Проверяются и заменяются только шесть файлов адаптера, API/worker и интерфейса. Все исходники проверяются до начала замены; при ошибке восстанавливается полный комплект и прежний образ. Запущенный WhatsApp, его адаптер и сессия, ключи, база и порт сохраняются. После `MAX_UPDATE_OK` обновите страницу браузера, выберите «Подключить канал» → «MAX», отсканируйте QR и подтвердите вход на телефоне. Затем проверьте текстовую отправку, новое входящее и историю. Для альтернативного входа нажмите «Войти по номеру телефона»; пароль, если MAX его запросит, относится к аккаунту MAX.

## Обновление списка диалогов и истории на Mac

Для существующей установки в `$HOME/Projects/omnicrm-local` используйте `scripts/update_mac_inbox.sh FULL_COMMIT_SHA [LOCAL_DIRECTORY]` **из выпуска с новым inbox**. Передавайте полный 40-символьный SHA опубликованного commit, указанный в инструкции выпуска. Скрипт скачивает исходники именно этого commit; `main`, короткий SHA и плавающая ветка не принимаются. Копия updater из нового выпуска может находиться вне установленного проекта, например в `/tmp`; повторная установка проекта не нужна.

Поддерживается исходная локальная установка `f4f533a`, в том числе с исправлением WhatsApp `bbaf270` и обновлением MAX `f063e5d`. По SHA256 проверяются все 12 заменяемых файлов до первой замены. Допускается и уже установленный целевой файл для повторной попытки того же выпуска. Неизвестные локальные изменения останавливают обновление; вручную удалять их ради обхода проверки не следует. Основной маркер установленной версии и маркеры прежних WhatsApp/MAX patches сохраняются, успешный новый выпуск записывается отдельно в `.omnicrm-inbox-patch`.

Сначала собирается отдельный образ, пока CRM продолжает работать. Затем на время резервного копирования и миграции останавливаются только API и worker. Updater создаёт PostgreSQL custom dump и проверяет его каталог через `pg_restore --list`, запускает миграцию **из нового образа**, а затем переключает API/worker с проверкой готовности. WAHA, PostgreSQL и их volumes не пересоздаются. `.env.local-docker`, Compose-файл и фактически используемый localhost-порт сохраняются; присутствующие в shell переменные другой разработки не подменяют ключи локальной CRM.

Резервная копия находится в `backups/inbox-<дата>-<идентификатор>/` с правами `0700`; файл `database.dump` имеет права `0600`. Там же сохраняются заменяемые исходники, ID прежнего образа и отметки завершённых этапов. Дамп содержит личную переписку и зашифрованные настройки аккаунтов; сам файл дампа дополнительно не шифруется. Файл ключей не копируется: сохраните существующий Fernet key отдельно. Не включайте этот каталог в архив проекта и не присылайте его содержимое в чат. Проверка каталога дампа не заменяет отдельное испытание восстановления БД.

При ошибке сборки, миграции или проверки нового приложения updater восстанавливает прежние исходники и образ. **Схема БД и данные автоматически не откатываются:** добавленные таблицы `0003_inbox` совместимы с прежним приложением и остаются на месте. Старый `migrate.py` отвергнет новую revision, поэтому при автоматическом возврате запускаются только API/worker с `--no-deps`; старую миграцию запускать нельзя. После такого возврата повторите исправленный inbox updater. Не удаляйте revision-таблицу, новые таблицы, дамп, ключи или volumes. Если во время обновления пользователь изменил конфигурацию, updater сохраняет правки и останавливает автоматический запуск с другими ключами — требуется проверить сообщение об ошибке и закрытую резервную копию.

После `INBOX_UPDATE_OK` обновите страницу браузера. Проверьте список диалогов, новое входящее, отметку прочтения и загрузку более ранней истории на своих подключённых аккаунтах. Состав доступной истории определяется мессенджером; обновление не восстанавливает сообщения, которые провайдер не отдаёт.

## Зафиксированные образы WhatsApp

Docker Registry проверен 2026-10-14. Голого Docker-тега `2026.9.2` нет: upstream публикует engine-prefixed теги. Инициализатор выбирает образ по архитектуре Docker daemon и сохраняет полный digest в `.env.local-docker`; эмуляция AMD64 на Apple Silicon не требуется.

| Docker host | Образ | Manifest digest |
|---|---|---|
| Intel/AMD `amd64` | `devlikeapro/waha:noweb-2026.9.2` | `sha256:be61f8cd7774ab22bd1b755cbc539f98d71d81d5ca83555fdddfa4fddd7924e1` |
| Apple Silicon / Linux `arm64` | `devlikeapro/waha:noweb-arm-2026.9.2` | `sha256:c7fba52db50312c8d0d05536f11ef136ac851c6b2baa11a883ea2d3d6d877f82` |

Манифест каждого тега содержит соответствующую Linux-архитектуру и provenance-attestation. Это отдельные архитектурные образы. При переносе уже созданной `.env.local-docker` на другую архитектуру сохраните все ключи и замените только `WAHA_IMAGE` точным значением для нового компьютера. Проверка registry и исходного API-контракта не заменяет live-тест с вашим номером и не подтверждает нагрузку 300 сотрудников.
