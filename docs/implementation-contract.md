# Internal implementation contract

Backend Python 3.12+, FastAPI, SQLAlchemy 2 synchronous repositories, PostgreSQL production / SQLite tests. Providers implement `app.adapters.base.Adapter` and never import core database. Adapter config contains private credentials and cursor/session data; core encrypts at rest. Workers own stable account shards through PostgreSQL session advisory locks and transactional `ShardLease` epochs. One lock connection serves a worker, rather than one connection per account. Personal-adapter disconnect revokes the provider session; official token-based adapters stop local processing and explicitly require provider-console token revocation separately.

API base `/api`. Auth: Bearer JWT from CRM, claims `sub`, `tenant_id`, `role` (`agent`/`admin`), `iss`, `aud`, `exp`. No shared browser admin secret. Development-only token route `/api/dev/token` returns demo agent token; forbidden production.

GET `/api/me` identity. GET/POST `/api/accounts`; account fields `id,channel,label,owner_id,state,public,created_at`. Create body `channel,label,config` (private per provider) owner defaults current user; admin may supply owner_id. Channel ids `telegram`, `whatsapp_cloud`, `whatsapp_web`, `max_bot`, `max_personal`, `sms_gateway`, `demo`. Admin POST `/api/accounts/{id}/assign` `{owner_id}`. POST `/api/accounts/{id}/actions` `{action,payload}` queues encrypted auth operation; GET `/api/jobs/{id}` status. `action=login/code/password/sync/disconnect`, provider-dependent. GET account exposes state and public auth response, never config. QR may be in public response to authorized owner only. POST `/api/accounts/{id}/disconnect` queues revoke.

GET `/api/conversations?account_id=...` returns array `{id,account_id,peer,title,last_message_at}`. POST `/api/conversations` `{account_id,peer,title}`. GET `/api/conversations/{id}/messages?before=integer&limit=100` chronological page sorted by `(created_at,id)`; `before` identifies the message tuple. Message `{id,conversation_id,provider_id,text,template,direction,status,error,created_at}`. POST same URL `{text,client_id:UUID,template?:{name,language,parameters}}` queues durable outbox and returns message (idempotency covers text and template). Templates only for WhatsApp Cloud. GET `/api/messages/{id}`. Poll frontend every 3 seconds while visible. Status values queued/sending/sent/delivered/read/failed/uncertain/received. Failed/uncertain not silently resent.

POST `/api/demo/inbound` `{conversation_id,text}` only explicit demo mode for local verification. Demo messages clearly labelled, no accidental real send. All account/conversation operations scoped by tenant and owner; admin tenant scope. Auth job payload removed after processing, audit excludes content/secrets.

Frontend is buildless ES module custom element `<omni-inbox>` with standalone index served by FastAPI. Host injects short-lived CRM JWT through element `.token` property (memory only), same origin deployment preferred. No iframe token in URL. Must show authentic capability states, no fake success.
